# 02. 피드백 → 메모리·스킬 → 다음 제작 적용

AI가 갑자기 똑똑해지는 게 아니라, 내가 준 피드백이 파일로 쌓이고 다음 세션이 그 파일부터 읽는 구조다.

```
내가 한 말
  │  (UserPromptSubmit 훅 hooks/capture_feedback.py — 원문을 memory/inbox.jsonl에 기록, 고칠 점으로 보이면 저장 절차를 상기)
  ▼
Claude가 고치고, feedback-loop 스킬로 분류해 저장
  ├─ 이번 영상만      → videos/<slug>/FEEDBACK-ITEMS.md
  ├─ 앞으로 계속      → memory/rules/<이름>.md + memory/INDEX.md
  ├─ 일하는 순서      → .claude/skills/<스킬>/SKILL.md
  └─ 기계로 잡을 사고 → tools/regressions.json
  ▼
다음 세션 시작 (SessionStart 훅 hooks/session_start.py — INDEX 목록 + 현재 영상의 미반영 피드백을 맥락에 넣음)
  ▼
Claude가 관련 규칙 원문을 열어 적용 → 결과물에 "적용한 규칙" 한 줄
  ▼
합본마다 tools/qa.py가 regressions.json을 다시 검사 (사람이 잊어도 기계가 막음)
```

## 1. 저장 예시

### 지속 규칙 — `memory/rules/number-reading.md`
```markdown
---
title: 숫자는 대본에 한글로
area: 대본
summary: 횟수·개수(번·개·명·시간·가지)는 고유어(한 번·세 가지), 번호·날짜·%는 한자어로 대본에 한글로 쓴다
since: 2026-10-25
---

**규칙.** 횟수·개수는 고유어, 번호·날짜·%는 한자어로 대본에 한글로 쓴다

**왜.** 숫자로 쓰면 음성이 '22번'을 '이십이 번'으로 읽었고, 받아쓰기도 숫자로 적어 검수가 못 잡았다

**어떻게 적용.** 대본 쓸 때 숫자를 한글로, 날짜 연음은 settings.pron에 소리 나는 대로
```
명령으로: `python tools/memory.py add number-reading --area 대본 --rule "…" --why "…" --how "…"` → INDEX 자동 갱신.

**왜 '왜'를 적나.** 규칙만 있으면 예외 상황에서 기계적으로 적용한다. 이유가 있으면 Claude가 "이 경우는 규칙의 목적과 다르다"를 판단할 수 있다.

### 이번 영상만 — `videos/<slug>/FEEDBACK-ITEMS.md`
```markdown
- [ ] v2-w3 로고가 글자로 나옴 → 심볼 로고로 (받은 판 v2-v3)
- [x] v1-s4 배경이 너무 어두움 → 밝기 0.78 (v1-v4 반영)
```
다른 영상에 옮기지 않는다. 한 번의 수정을 규칙으로 키우면 다음 영상을 엉뚱하게 망친다. 같은 지적이 두 번째로 나오면 그때 규칙으로 올릴지 묻는다.

### 재발 사고 — `tools/regressions.json`
```json
{"id": "lower-latin", "kind": "script", "pattern": "(?<![A-Za-z])[a-z]{2,}(?![A-Za-z])",
 "symptom": "소문자 'ai'를 음성이 '아이'로 읽어 'AI 시장'이 'I 시장'이 됨", "fix": "대본 영어는 대문자"}
```
이 줄이 있으면 다음부터 대본에 소문자 영어가 들어간 합본은 `qa.py --gate`를 통과하지 못한다.

## 2. 다음 작업에서 불러오는 방식

| 언제 | 무엇이 | 어떻게 |
|---|---|---|
| 새 세션·`/clear`·대화 요약 뒤 | `session_start.py` | INDEX 목록(짧음) + 현재 영상 미반영 피드백 + 분류 안 된 피드백 수를 맥락에 넣음 |
| 단계를 시작할 때 | Claude | INDEX에서 관련 규칙을 골라 원문을 연다(`CLAUDE.md` 1번) |
| 사용자 말마다 | `capture_feedback.py` | 원문 기록 + 고칠 점으로 보이면 저장 절차 상기(판단은 Claude가 한다) |
| 합본마다 | `qa.py` | 재발 목록 검사 |

목록만 넣고 본문은 필요할 때 여는 이유: 규칙이 100개가 넘어도 매 세션 맥락이 가볍다.

## 3. 직접 확인해 보기

1. 키트 폴더에서 Claude Code 새 세션 → "화면에 '예시' 칩 붙인 장면 하나 HTML로 만들어 줘" → `no-label-chips` 규칙을 근거로 칩 없이 만들거나 이유를 말해야 한다.
2. "앞으로 엔딩 멘트는 '다음 영상에서 봬요'로 해" → 고친 뒤 `memory/rules/`에 새 파일, INDEX에 한 줄이 생겨야 한다.
3. `/clear` 뒤 "엔딩 대본 써 줘" → 2번 규칙이 적용돼야 한다.
4. `python tools/memory.py inbox` → 분류 안 된 후보가 남았는지.

## 4. 규칙 관리

- 틀린 규칙은 파일을 지우고 `python tools/memory.py reindex`.
- 비슷한 규칙이 생기면 합친다(`python tools/memory.py search <낱말>`).
- 시작 규칙 14개는 키트 제작자의 채널에서 나온 것이다. 내 채널과 안 맞는 건 지운다.
- 여러 PC에서 같이 쓰려면 이 폴더를 개인 비공개 git 저장소로 관리한다(`.gitignore`가 미디어·원문 기록을 뺀다).
